# 前端监测设计说明

## 面向手机还是电脑

当前前端按双场景设计：

- 电脑端：用于开发、地面测试和数据排查，需要同时看到趋势图、模块状态、定位状态和综合判断。
- 手机端：用于现场连接 ESP32 SoftAP 后快速查看，重点是当前读数、是否异常、是否定位。

因此页面采用响应式布局：宽屏显示多列仪表盘，窄屏自动变成单列。

## 只呈现数据是否足够

不够。空气质量监测如果只显示原始数值，现场人员很难判断：

- 当前数值是否正常
- 是否只是瞬间波动
- 哪个指标最值得关注
- GPS 未定位时数据是否具备空间意义
- 传感器是否离线或处于预热状态

所以前端应该至少包含读数、参考范围、趋势、模块状态和综合结论。

## 参考范围

当前页面内置了开发阶段参考值：

| 指标 | 正常参考 |
|---|---:|
| TVOC | 小于 0.60 mg/m3 |
| 甲醛 CH2O | 小于 0.10 mg/m3 |
| CO2 | 小于 1000 ppm |
| PM | 小于 35 ug/m3 |

这些值用于现场快速判断，不等同于正式检测报告。后续可根据项目采用的国标、校园验收标准或老师要求调整。

## 是否需要绘制图像

需要。趋势图比单点数字更有价值：

- 能看出传感器预热后的稳定过程。
- 能判断异常是瞬时尖峰还是持续升高。
- 能辅助选择无人机悬停采样位置。
- 能发现接线松动、模块离线、数据卡死等问题。

当前前端已经绘制最近约 60 秒的 TVOC、CH2O、CO2、PM 趋势。

## 是否需要整合数据

需要。单个传感器只能说明一个维度，整合后才能形成采样记录：

```text
时间 + GPS 位置 + TVOC + CH2O + CO2 + PM + 模块状态
```

后续可进一步扩展为空间热力图、航线采样点表格和异常点列表。

## 是否需要分析总结

需要，但开发阶段应保持简单、可解释。

当前前端已经给出：

- 综合判断：良好、关注、异常、等待定位
- 异常指标说明
- GPS 未定位提示
- 传感器状态提示

后续可以增加：

- 最近 1 分钟均值、最大值、最小值
- 超限持续时间
- 异常采样点列表
- 飞行任务结束后的自动报告
